# Instahyre Search Skill

Search job listings from Instahyre's public JSON endpoints — a product/startup-focused
hiring platform for the Indian tech market. No authentication, no API key, and
**zero runtime dependencies** — it runs with just `bun`.

> This is a market-specific portal skill generated by `/add-portal`. Per repo policy,
> it lives in this fork rather than being merged upstream.

## Important limitation: client-side filtering only

Instahyre's anonymous `/api/v1/job_search` endpoint does **not** honor `keywords`/
`locations` filter params for unauthenticated requests — it always returns the same
generic, paginated "curated opportunities" feed regardless of what's passed. Real
personalized/filtered search only works for logged-in candidates.

To still provide useful search, this CLI scans up to 40 raw pages (~1,400 postings)
of the anonymous feed per `search` call and filters **client-side** by matching
`--query` against each posting's title/keywords, and `--location` against its
locations string. This is slower and less exhaustive than a true server-side search
(like `linkedin-search`) — treat results as a best-effort sample, not guaranteed
full recall. `--jobage` is not supported at all, since the portal's public feed
does not expose posting dates.

robots.txt for this site has no disallow rules (fully open), so no personal-use
warning is required, but keep request volume reasonable regardless.

## When to use this skill

- Search for software/product engineering job openings in India (any city) or remote,
  especially at product companies and high-growth startups
- Get the full description of a specific Instahyre job listing

## Commands

### Search job listings

```bash
bun run .agents/skills/instahyre-search/cli/src/cli.ts search [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — keyword search (title, skill, or role), matched client-side.
- `--location <text>` / `-l <text>` — location substring (e.g. `"Bangalore"`), matched client-side.
- `--jobage <days>` — **not supported**; prints a warning and is ignored.
- `--page <n>` — page number (1-indexed) over the filtered result set.
- `--limit <n>` / `-n <n>` — results per page (and client-side cap). Default 10.
- `--format json|table|plain` — default `json`.

### Fetch full job detail

```bash
bun run .agents/skills/instahyre-search/cli/src/cli.ts detail <id|url> [--format json|plain]
```

`id` is the job ID from `search` results (e.g. `432767`). You may also pass a full
Instahyre job URL (`https://www.instahyre.com/job-432767-.../`). Returns the full
description, employment type (full-time/internship), experience range, and job function.

## Usage examples

```bash
# Backend engineer roles in Bangalore
bun run .agents/skills/instahyre-search/cli/src/cli.ts search -q "backend engineer" -l "Bangalore" --format table

# SDE II roles anywhere, more results per page
bun run .agents/skills/instahyre-search/cli/src/cli.ts search -q "SDE II" --limit 20 --format table

# Full details for a specific job
bun run .agents/skills/instahyre-search/cli/src/cli.ts detail 432767 --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing IDs to `detail` |
| `table` | Quick human-readable scanning |
| `plain` | Reading a single job's full detail (`detail` command) |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`. Non-fatal warnings (e.g. unsupported `--jobage`) are written to stderr as `{ "warning": "..." }` without affecting the exit code.

## Notes

- Data is from Instahyre's public `/api/v1/job_search` and `/api/v1/employer_public_jobs/<id>` endpoints — no credentials required, but see the client-side-filtering limitation above.
- The site is a client-rendered AngularJS SPA; these endpoints were found via browser network inspection, not by reading page HTML (which only shows unrendered templates). See `url-reference.md` if the portal changes and this needs updating.
- Instahyre may rate-limit; the CLI retries 429/5xx with exponential backoff.
- Job IDs are numeric (e.g. `432767`) — pass them as-is to `detail`.
- Best suited for backend/full-stack/product-engineering searches; Instahyre's own stats show "Backend Development" as its single largest job-function category.
