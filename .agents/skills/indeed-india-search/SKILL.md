# Indeed India Search Skill

Search live job listings from Indeed India's public, server-rendered job-search
pages. No authentication, no API key, and zero *package* dependencies — it
runs with `bun` plus the system `curl` binary (see "Transport note" in
`cli/README.md`: Bun's native `fetch()` is consistently 403'd by Indeed's WAF
due to a TLS-fingerprint mismatch, while plain `curl` works fine).

> This is a market-specific portal skill generated by `/add-portal`. Per repo
> policy, it lives in this fork rather than being merged upstream.

## Why Indeed and not Naukri

`in.indeed.com`'s `robots.txt` explicitly lists `Claude-User` and
`Claude-SearchBot` with `Allow: /` — this site's policy explicitly welcomes AI
agents. Naukri's `robots.txt`, by contrast, explicitly disallows the same
agent names, so this framework does not scrape Naukri. Two other candidates
(Hirist, Wellfound) were investigated and rejected: Hirist has fingerprint-based
bot detection that silently serves empty data to non-browser clients, and
Wellfound serves an explicit DataDome CAPTCHA challenge to plain HTTP clients.
See `url-reference.md` for the full investigation notes.

## When to use this skill

- Search for job openings in India (any city) or remote
- Filter by recency (posted within N days) via `--jobage`
- Get the full description, company, location, and salary (when listed) of a specific Indeed job posting

## Commands

### Search job listings

```bash
bun run .agents/skills/indeed-india-search/cli/src/cli.ts search [flags]
```

Key flags:
- `--query <text>` / `-q <text>` — keyword search (title, skill, or role).
- `--location <text>` / `-l <text>` — city/region, e.g. `"Bangalore"`, `"Bengaluru, Karnataka"`.
- `--jobage <days>` — posted within N days (real server-side filter via Indeed's `fromage` param).
- `--page <n>` — page number (1-indexed, 10 results per page).
- `--limit <n>` / `-n <n>` — cap total results emitted (client-side).
- `--format json|table|plain` — default `json`.

### Fetch full job detail

```bash
bun run .agents/skills/indeed-india-search/cli/src/cli.ts detail <jk|url> [--format json|plain]
```

`jk` is the job key from `search` results (e.g. `01e6756464a2a91b`). You may also pass a full
`/viewjob?jk=...` or `/rc/clk?jk=...` URL. Returns the full description, company, location, and salary (when Indeed shows it).

## Usage examples

```bash
# Backend engineer roles in Bangalore
bun run .agents/skills/indeed-india-search/cli/src/cli.ts search -q "backend engineer" -l "Bangalore" --format table

# SDE II roles, posted in the last 14 days
bun run .agents/skills/indeed-india-search/cli/src/cli.ts search -q "SDE II" -l "Bengaluru, Karnataka" --jobage 14 --format table

# Full details for a specific job
bun run .agents/skills/indeed-india-search/cli/src/cli.ts detail 01e6756464a2a91b --format plain
```

## Output formats

| Format | Best for |
|--------|----------|
| `json` | Default — programmatic use, passing IDs to `detail` |
| `table` | Quick human-readable scanning |
| `plain` | Reading a single job's full detail (`detail` command) |

All errors are written to **stderr** as `{ "error": "...", "code": "..." }` and the process exits with code `1`.

## Notes

- Data is from Indeed India's public, server-rendered `/jobs` and `/viewjob` pages — no credentials required.
- Job cards do not expose a reliably parseable posting date in the markup, so the `date` field in results is always `null` — but `--jobage` still filters correctly server-side.
- Salary is included when Indeed shows it on the listing (common for Indian tech postings).
- Indeed may rate-limit; the CLI retries 429/5xx with exponential backoff.
- Job IDs (`jk`) are 16-character hex strings — pass them as-is to `detail`.
